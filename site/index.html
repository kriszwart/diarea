    The Leak Score

    Four stages of grief

    Eight checks roll up into one score from 0 to 100. Critical findings hurt most. Lower is better, which is the opposite of everything else you measure.

    1. 0 to 14

      Sealed

      Tight. An agent would come away with very little. Frame it.

    2. 15 to 39

      Seeping

      A few things are showing. Worth a wipe-down before the weekend.

    3. 40 to 69

      Leaking

      Your logic and data are readable from the browser. Cancel the offsite.

    4. 70 to 100

      Gushing

      Most of how this works is sitting in the open. Colander AI lives here.

    What it sniffs out

    Eight things an agent loves to find

    • Source maps in productionYour original source, comments and all. Gift-wrapped.
    • Secrets in client codeKeys and tokens in shipped JavaScript. Reported as a prefix and a length, never in full.
    • Client-side scoringWeightings and thresholds running in the browser. The bit that makes you different.
    • Fat hydration payloadsBoot blobs carrying ids, flags and fields nobody sees on screen.
    • Readable bundlesUn-minified code with the TODOs still attached.
    • A self-mapping APIEvery endpoint listed in the bundle. GraphQL introspection left on.
    • Chatty hidden fieldsHidden inputs and data attributes holding prices, roles and flags.
    • A stack fingerprintNot a leak alone, but it tells a reader which known tricks to try.

    Install

    Three ways to check yourself

    One engine, three doors. Same checks, same score, wherever your code ships.

    Chrome extension

    Open your own site, click the icon, get the score. Nothing leaves the browser.

    git clone https://github.com/kriszwart/diarea
cd diarea && npm install && npm run build:extension

    Then load extension/ unpacked at chrome://extensions. Web Store listing on the way.

    CLI

    Scan build output with no browser, or a live URL with one. JSON for machines, cheek for humans.

    npx diarea scan dist/index.html
npx diarea scan https://your-site.com --fail-on 40

    Exit codes: 0 fine, 1 over your line, 2 could not scan.

    GitHub Action

    Fail the build when the score creeps up. The findings land in the job summary.

    - uses: kriszwart/diarea@v0
  with:
    target: dist/index.html
    fail-on: 40

    Add strict: true to fail on any critical finding.

    The honest bit

    Diarea is a diagnosis, not armour. You cannot stop an agent reading your frontend: whatever the browser receives, it receives too. The real fixes happen elsewhere, and Diarea points you at them.

    • Run the scoring engine on the server. Ship verdicts, never the rules.
    • Return only the fields the page renders.
    • Strip source maps and minify what ships.
    • Keep secrets off the client. Publishable keys only.
    • Guard the API with auth, quotas and rate limits.

    FAQ

    Questions we get, mostly about the name

    Is the name a typo?

    No, it is a pun with a backstory. REA is an agent that reverse-engineers products. Diarea is its defensive counterpart for the frontend. They share their last letters, and one of them is about leaks. We regret nothing.

    Can I scan someone else's site?

    Please do not. Diarea is defensive: scan sites you own or are authorised to test. It reads what any browser could read, never exploits anything, and hides secret values even in its own reports. If you want a safe target, Colander AI is all yours.

    Does anything leave my machine?

    No. The extension and CLI make no requests of their own beyond reading the page you point them at. No telemetry, no accounts, no storage. This website loads nothing from anyone else either. Not even fonts.

    A low score means I am safe, right?

    It means nothing obvious is leaking from the frontend. Your API, your auth and your servers are a different conversation. Think of it as a smoke alarm, not a fire brigade.

    How do I add a check?

    Every rule lives in one file, src/checks.js. Add yours, give Colander AI a leak that trips it, and open a pull request. The contributing guide has the details.
