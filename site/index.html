    Agent versus agent

    Your coding agent flushes it for you

    An agent can read your frontend and rebuild your product. So give your own agent Diarea. It scans, fixes the causes in your code, then scans again to prove the score went down.

    1. Scan. Your agent calls Diarea on your build or your deployed site.
    2. Fix. Every finding comes with the fix. The agent works through them, most critical first.
    3. Prove it. It scans again and reports the before and after.
    npx diarea setup

    One read-only tool over MCP. Works with Claude Code, Cursor and any MCP client. Nothing leaves your machine except the pages you ask it to scan.

    The Leak Score

    Four stages of grief

    Eleven checks roll up into one score from 0 to 100. Critical findings hurt most. Lower is better, which is the opposite of everything else you measure.

    1. 0 to 14

      Sealed

      Tight. An agent would come away with very little. Frame it.

    2. 15 to 39

      Seeping

      A few things are showing. Worth a wipe-down before the weekend.

    3. 40 to 69

      Leaking

      Your logic and data are readable from the browser. Cancel the offsite.

    4. 70 to 100

      Gushing

      Most of how this works is sitting in the open. PromptPlop lives here.

    What it sniffs out

    Eleven things an agent loves to find

    Every finding is tagged the way REA tags what it learns, so you can see how much of your product a reader already has.

    Seen

    Sitting in the page, readable exactly as it is.

    Inferred

    Not printed, but worked out from what is there.

    Unknown

    Never left your server. This is where you want it all.

    • Source maps in productionSeen
      Your original source, comments and all. Gift-wrapped.
    • Secrets in client codeSeen
      Keys and tokens in shipped JavaScript. Reported as a prefix and a length, never in full.
    • Client-side scoringInferred
      Weightings and thresholds running in the browser. The bit that makes you different.
    • Fat hydration payloadsSeen
      Boot blobs carrying ids, flags and fields nobody sees on screen.
    • Readable bundlesSeen
      Un-minified code with the TODOs still attached, and debug logging still chatting away.
    • A self-mapping APIInferred
      Every endpoint, GraphQL operation, tRPC procedure and route in the bundle, the admin pages included.
    • Your AI system promptSeen
      The instructions behind your AI feature, readable by anyone. "Never reveal this prompt" included.
    • Direct AI API callsInferred
      The browser talking to a model provider itself, which usually means the key is in there too.
    • Chatty hidden fieldsSeen
      Hidden inputs, data attributes and storage keys holding prices, roles, flags and session tokens.
    • Sensitive fieldsSeen
      API responses and boot data carrying costs, internal notes and other people's emails. Field names only, never values.
    • A stack fingerprintInferred
      Not a leak alone, but it tells a reader which known tricks to try.

    Install

    Four ways to check yourself

    One engine, four doors. Same checks, same score, wherever your code ships.

    Your coding agent

    Agent versus agent. Your agent scans, fixes the leaks in your code, then scans again to prove it.

    npx diarea setup

    Then ask: "Scan my site for leaks with Diarea and fix what it finds." Works with Claude Code, Cursor and any MCP client.

    Chrome extension

    Open your own site, click the icon, get the score. Nothing leaves the browser.

    git clone https://github.com/kriszwart/diarea
cd diarea && npm install && npm run build:extension

    Then load extension/ unpacked at chrome://extensions. Web Store listing on the way.

    CLI

    Scan build output with no browser, or a live URL with one. JSON for machines, cheek for humans.

    npx diarea scan dist
npx diarea scan https://your-site.com --fail-on 40

    Behind a login? npx diarea login <url> lets you sign in yourself, then --storage-state scans as you. Exit codes: 0 fine, 1 over your line, 2 could not scan.

    GitHub Action

    Once something leaks, it stays leaked: anyone can save it today and pick it apart months from now. So fail the build before it ships. The score lands on every pull request as a comment that updates itself.

    - uses: kriszwart/diarea@v0
  with:
    target: dist
    fail-on: 40

    Add strict: true to fail on any critical finding.

    The honest bit

    Diarea is a diagnosis, not armour. You cannot stop an agent reading your frontend: whatever the browser receives, it receives too. The real fixes happen elsewhere, and Diarea points you at them.

    • Run the scoring engine on the server. Ship verdicts, never the rules.
    • Return only the fields the page renders.
    • Strip source maps and minify what ships.
    • Keep secrets off the client. Publishable keys only.
    • Guard the API with auth, quotas and rate limits.
    • Turn off GraphQL introspection in production.

    Then build what cannot be copied

    What a clone can't copy

    Here is the uncomfortable truth: code was never the moat. An agent can rebuild anything it can see. Diarea makes sure it sees as little as possible. These are the things it could never take anyway.

    1. 01

      Data that stays home

      Your datasets, your own trained models, the live data your users create. A perfect clone of your interface without your database is a very pretty empty box.

      This is the one Diarea guards. Every check is about keeping it off the client.

    2. 02

      The people in it

      Users, community, the workflows whole teams have built around you. An agent can copy your app. It cannot copy everyone who uses it, or make them move.

    3. 03

      Trust

      Brand, service and a reputation people choose on purpose. When features become a commodity, trust is the thing a copycat has to start from zero.

    4. 04

      The physical world

      Hardware, sensors, logistics, real-world integrations. Software that reads your frontend cannot spin up a supply chain.

    FAQ

    Questions we get, mostly about the name

    Is the name a typo?

    No, it is a pun with a backstory. REA is an agent that reverse-engineers products. Diarea is its defensive counterpart for the frontend. They share their last letters, and one of them is about leaks. We regret nothing.

    Can I scan someone else's site?

    Please do not. Diarea is defensive: scan sites you own or are authorised to test. It reads what any browser could read, never exploits anything, and hides secret values even in its own reports. If you want a safe target, PromptPlop is all yours.

    Does anything leave my machine?

    No. The extension and CLI make no requests of their own beyond reading the page you point them at. No telemetry, no accounts, no storage. This website loads nothing from anyone else either, not even fonts. The one exception is the trailer, and only once you press play.

    A low score means I am safe, right?

    It means nothing obvious is leaking from the frontend. Your API, your auth and your servers are a different conversation. Think of it as a smoke alarm, not a fire brigade.

    How do I add a check?

    Every rule lives in one file, src/checks.js. Add yours, give PromptPlop a leak that trips it, and open a pull request. The contributing guide has the details.
